# 사이 · 취향이 만나는 곳

흰 배경과 검은 글씨의 iOS / Android 앱. 친구 두 명 또는 모임 참여자의 **공통 관심사와 연결 후보**를 보여줍니다. 대화 질문을 생성하지 않습니다.

## 실행

Node.js 24 이상에서 `npm install` 후 `npm run server`를 실행하세요. `.env`에 `EXPO_PUBLIC_API_URL=http://컴퓨터의LAN주소:8788`을 지정하고 `npm start` 후 휴대폰 Expo Go로 QR을 스캔합니다. 휴대폰과 컴퓨터가 같은 Wi-Fi에 있어야 합니다. 개발 빌드 및 설치 파일 안내는 [mobile/README.md](mobile/README.md)에 있습니다.

## 구현한 기능

- 공유 여부를 선택하는 관심사 프로필, 프로필 링크/QR
- 친구 요청·수락과 두 사람 비교
- 코드/링크로 참여하는 모임, 인원 상한 없음
- 동일 관심사·관련 분야 구분, 참여자와 원문 근거 표시
- 자유 입력의 관심사 추출: Gemini 서버 API로 정리하고 후보를 선택해 저장
- 기기 세션 저장, 서버 SQLite 저장, 프로필 삭제

## AI 설정

- **취향 정리:** Gemini 서버 API가 좋아함·피하고 싶음·새로운 관심 질문의 답에서 원문에 있는 관심사만 제안합니다. 사용자가 선택한 항목을 저장합니다. 생성 모델 다운로드는 없습니다. 서버 비밀 설정 `GEMINI_API_KEY`, 모델 `GEMINI_MODEL=gemini-3.1-flash-lite`를 사용합니다. 무료 API는 한도와 Google의 데이터 사용 정책이 적용되므로 전송 전 안내·동의를 받습니다.
- **유사도:** Qwen3-Embedding-0.6B ONNX q8을 브라우저 Web Worker에서 실행합니다. 관심사 벡터의 코사인 유사도를 계산하며 새 학습·모델 확장은 하지 않습니다. 첫 의미 비교에는 약 614MB 다운로드가 필요합니다. 기기 메모리가 부족하면 기본 관심사 비교를 사용합니다.
- 정확한 항목 정규화·분야 규칙을 함께 사용하며 유사도 점수는 관계 성공 확률이 아닙니다.

## 활동에서 관심사 가져오기

`내 취향 → YouTube·LinkedIn에서 관심사 가져오기`는 가입 직후 프로필 설정과 수정에서도 열 수 있습니다.

- YouTube: 읽기 전용 OAuth, PKCE·일회용 state·브라우저 쿠키·로그인 세션 검증. refresh token으로 연결을 유지하고, 토큰은 계정에 귀속된 AES-GCM 암호화로 D1에 저장합니다. 최대 10개 본인 재생목록, 영상 100개, 구독 채널 50개의 제목·설명을 가져옵니다. 시청 기록을 가져오는 기능은 아닙니다. 연결 해제 시 Google 토큰을 취소합니다.
- LinkedIn: 본인 공개 프로필 링크를 Bright Data LinkedIn people profiles (`gd_l1viktl72bvl7bjuj0`)로 수집합니다. 전공·학력·소개·경험 등의 공개 내용만 보관하며 이름·이메일·연락처·추천 인맥은 가져오지 않습니다. 프로필마다 공개 내용이 달라 전공·관심사 필드가 없을 수 있습니다. 비동기 수집 결과를 확인한 뒤 사용할 문장을 선택합니다. 일반 LinkedIn 로그인 API로 전체 학력·관심사를 받는 기능은 아닙니다.
- 원문 자료는 본인 계정만 읽을 수 있습니다. Gemini에 보낼 문장은 최대 1,000자로 확인·수정하고 전송에 동의합니다. 후보는 기본 비공개로 추가하며 저장 전 선호·공유 여부를 확인합니다. 원문을 모임 분석에 바로 넣지 않습니다.

서버 설정은 `.env.example`을 참고하세요. 운영 값은 Sites 비밀 설정에 보관하며 GitHub 및 브라우저 번들에 포함하지 않습니다. 현재 Google 앱은 테스트 모드이므로 등록된 테스트 계정만 YouTube를 연결할 수 있습니다. 테스트 모드에서는 Google 정책에 따라 재승인이 필요할 수 있습니다. 일반 사용자 공개에는 동의 화면 구성·Google 검증이 별도로 필요합니다.

## 친구 선택으로 모임 만들기

친구 선택 → 모임 이름·최대 테이블 인원 3/4/5명 → 편성안 비교·세부 근거 → 모임 만들기·참여 초대 순서입니다. 서로 수락한 친구만 직접 초대할 수 있고, 친구가 참여를 수락해야 구성원으로 등록됩니다. 초대 중인 편성은 제안으로 표시하며 모임 분석은 실제 참여자만 사용합니다. 기존 모임에서는 참여자만 선택해 다시 편성하고 주최자가 저장합니다.

## 가입과 검증

아이디·비밀번호·비밀번호 확인으로 가입한 다음 프로필을 설정합니다. 비밀번호는 scrypt와 개별 salt로 저장하고 세션은 30일입니다. Instagram·LinkedIn 프로필 링크는 선택 항목이며 친구 공개를 켠 경우 서로 수락한 친구만 볼 수 있습니다. Instagram OAuth·게시물 수집은 포함하지 않습니다.

`node --test tests/integrations.test.mjs`는 OAuth 재사용·다른 계정 복호화 차단, 개인 원문 분리, 가져올 재생목록 권한, 연결 해제와 토큰 갱신의 경쟁, Gemini 근거·한도, 친구 초대 수락을 검사합니다. 기존 smoke 검사, TypeScript 검사와 웹 빌드를 실행합니다. 실제 네이티브 기기·스토어 배포는 별도로 확인해야 합니다.

## 모임 구성
채팅 기능 없이 모임 검색과 참여자 목록, 공통 관심사 랭킹, 소그룹 제안을 제공합니다. 랭킹은 참여자 수 우선, 동일 관심사 우선입니다. 소그룹은 모든 구성원 쌍에 접점이 있는 complete-link 방식으로 최대 3~6명을 묶습니다. 점수는 각 사람의 공유 긍정 취향 중 연결된 항목 비율의 양방향 평균입니다. 동일 항목=1, 관련 분야=0.6, AI 후보=임베딩 코사인값(0.75 이상)을 가중치로 사용합니다. 점수는 관계 성공 확률이 아니며, 연결 근거가 없는 사람은 배정하지 않습니다. AI 실행 전에는 기본 공통점, 실행 후에는 의미 유사도를 반영합니다. 공유 회피 항목은 추천에서 제외하고 비공개 항목은 비교하지 않습니다.

## 기존 DB 변경 기록 정합성
기존 공개 사이트의 Worker가 먼저 설치한 Instagram 컬럼은 배포 전 D1 스키마에서 확인했습니다. 아직 기록되지 않아 실패한 0001 마이그레이션은 해당 컬럼 존재를 검증하고 변경 기록을 등록하도록 수정했습니다. 운영 Worker는 스키마를 변경하지 않습니다. 신규 로컬 DB와 테스트에서는 기존 사이트의 기준 스키마를 먼저 준비합니다. 이 마이그레이션 기록은 해당 기존 Site를 기준으로 하므로 완전히 새로운 Site로 복제할 때는 별도의 초기 스키마를 준비해야 합니다.

## 프로필 사진
프로필 만들기·수정에서 JPG/PNG/WebP 사진을 선택하고 변경·삭제할 수 있습니다. 웹에서는 5MB 이하 원본을 브라우저에서 중앙 정사각형으로 잘라 256px JPEG로 변환하고, 80,000자 이하의 작은 미리보기만 DB에 저장합니다. 원본·EXIF는 저장하지 않습니다. 사진은 공개 프로필 링크, 친구 및 모임 구성원 목록에서 표시됩니다. 서버는 JPEG 형식과 크기를 검증합니다. 네이티브에서도 Expo 이미지 처리로 256px로 줄입니다.

가입 때 입력한 Instagram·LinkedIn은 인증된 계정의 초기 프로필 입력값으로 임시 저장합니다. 프로필 완성 전 새로고침·재로그인해도 복원됩니다. 최초 프로필 저장 시 기본 비공개로 반영하고 계정의 임시 복사본을 비웁니다. 프로필에서 삭제한 링크가 초기 값 때문에 다시 나타나지 않습니다. `node backend/onboarding-links-smoke.mjs`에서 이 흐름을 검증합니다.
LinkedIn 가져오기는 프로필 링크에서 공개된 전공·소개·전문 분야를 읽는 방식입니다. 이미지·OCR·PDF 업로드는 제공하지 않습니다.
